# Changelog

Newest first. `spec.md` says how nykma works now. This file says what changed and why.

## 2026-11-22

### Fixed: the desk turning black on nykma-launch
- **Why.** The desk crashed again on nykma-launch: black blocks across the viewer, the panels and the timeline. That's Chrome running out of GPU memory. The project page alone held about 1.3 GB, against 280 MB for lidim. Almost all of it was the timeline's filmstrips. Each strip mounts the scene at full size and shrank it with `transform: scale()`, and Chrome rasterizes a 3D-tilted plane (the ad's wall of clips) near its full layout size whatever the scale: one strip of the end card held about 430 MB for a picture 60 px tall. The images, the blur and the box shadows weren't the cost; hiding them changed little.
- **What** (`src/board/frame.tsx`, spec.md §10.4). A strip shrinks each frame with CSS `zoom`, so the scene is laid out at the strip's size and rasterized at it. Three frames of the end card went from about 1 GB to under 100 MB, and the whole page loaded at about 270 MB. The strips look the same, give or take a pixel.
- **Still heavy.** Playing nykma-launch in the viewer still peaks around 1 GB while the wall scenes play, since the viewer draws them at full size.
- **Tested.** Typecheck, and GPU memory measured in headed Chromium from Windows' GPU counters: each wall scene's strip with `transform` and with `zoom`, compared side by side, and the whole desk page loaded and playing.

### Fixed: the chat's message box
- **Why.** The user said the agent's message box looked and acted weird: one line tall with scroll arrows, a red border, a light-blue chip on a red tint and a faded red send button. The box measured its height while the Agent tab was hidden, read 0, and kept it until you typed.
- **What** (`src/desk/Chat.tsx`, `desk.css`). The box measures again whenever its width changes (a hidden tab has none) and skips a measure taken while hidden. It has whole-pixel lines and no scrollbar until its text passes 220px. It's a quiet card that lifts to a neutral border when you type, not the accent red. Chips are neutral. The send button is grey until there's something to send. The hint says Shift+Enter makes a new line, and a green dot pulses while the agent works.
- **Tested** in Playwright on lidim: hidden then shown, one line, several lines, past the maximum, cleared, typed and switched tabs, the chat panel at 280, 700 and 340px, and both themes. Typecheck.

### Fixed: the desk showing no scenes
- **Why.** After an agent built lidim, the desk showed no scenes for any ad. Its `/api/registry` request never answered: a load of `src/registry.ts` through Vite's SSR loader had stuck, and every later poll waited on it, with no error. The ad's code was fine (a fresh Vite server loaded all 92 videos), and the desk recovered as soon as it restarted.
- **What** (`scripts/lib/desk.ts`). The desk runs one registry load at a time however often it polls. A load that takes over 45 seconds fails with an error that says to restart the desk if it keeps happening, and the next poll starts on a fresh module runner with the module graph invalidated. Typecheck; the registry loads in about a second after the restart.

### Changed: the desk edits like an editor: drag, scrub, text anywhere, effects and history
- **Why.** Trying the new desk, the user found: the timeline's playhead couldn't be dragged, only clicked; every change reloaded the page and dropped them back out; many things couldn't be changed (clicking a word didn't let them change it); nothing could be dragged; and there was no undo history. They asked for much more control, kept clean and easy, an effects tab for transitions between scenes and effects on objects, and undo with a history to go back to.
- **No more reloads** (spec.md §10.3). An edit to an ad's code made Vite reload every open page, the desk with it: `board.html` had no hot-update boundary. `src/registry.ts` now accepts its own update and hands the new registry to the frames, which draw it in place on the same frame with the same selection.
- **Scrubbing** (§10.3, §10.4). Drag the playhead, anywhere on the ruler or an empty part of a track; a scrub bar under the viewer does the same, with a tick per scene. The timeline's top edge drags to make it taller, and the filmstrips grow with it.
- **Dragging in the viewer.** Drag the selected element to move it (Shift: one axis), a corner to scale it, live, saved on release as its `translate` or `scale` (or its nudge knob). Double-click edits its text.
- **The inspector** (§10.13) is rebuilt in folding sections: Text (edited where the ad writes it, even in a constant, a list or a parent's prop: the desk matches what the element shows against the ad's string literals, Hebrew included), Layout (X, Y, scale, rotate), Type, Appearance, Effects, More from the code, Knobs. A value the code doesn't set can be added. Number labels drag to change the value and the viewer shows it live before it's saved; colour swatches open a live picker.
- **Effects** (§10.13, §5, §10.4). An Effects tab: entrances, loops and exits for an element, written to its `data-fx` attribute, which the engine applies on every frame, in the viewer and the render alike (`src/engine/fx.ts`); and 21 transitions into a scene (crossfade, dips, slides, pushes, whips, zooms, blur, wipes, iris), written to `story.json`'s `transitions`, which never move a scene or a cue: the outgoing scene holds its last frame under the incoming one (`src/engine/transitions.ts`). Tiles preview with the engine's own maths on hover; diamonds on the timeline mark transitions. `validate` warns about ones that can't play.
- **History** (§10.13). Every desk write to an ad (code, `tune.json`, `story.json`) is one labelled entry in `out/<slug>/desk-history.json`; a History tab lists them, goes back to any point and resets all, and Undo/Redo sit in the top bar (Ctrl+Z, Ctrl+Shift+Z). A step that would overwrite a file the agent or an editor changed since is refused, naming the file. The source API can now edit a literal elsewhere in the ad, add and remove style properties, and set `data-*` attributes.
- **Tested.** Typecheck. In Chromium against the running desk, on kav-echad with its folder backed up: an edit shows in the viewer with no reload of the desk; scrubbing on the ruler and the scrub bar; picking the Hebrew headline finds its text in `KavEchad.tsx` and the edit shows; dragging it writes a `translate`; a Push left into scene 3 writes `story.json` and plays mid-push in the viewer; a Fade up entrance writes `data-fx`; History lists them, two Ctrl+Z put the files back byte for byte, Ctrl+Shift+Z redoes, Reset all clears it, and the folder matched the backup after. ### Fixed: what checking the new desk turned up
- **Scripts and the desk no longer step on each other.** A script's Vite server (render, stills, validate) shared the dev server's dependency cache with different settings, so every run rebuilt it with only React in it and the open desk went blank with "Outdated Optimize Dep". Scripts now keep their own (`node_modules/.vite-scripts`, `scripts/lib/videos.ts`). They also no longer start the publishing clock, which had let a render post approved posts and lock a desk started during it out of posting.
- **Timeline and inspector.** Switching takes right after an edit no longer carries the old take's story into the new one. A trim stores only the ends you moved, so a scene the agent later lengthens isn't cut. The last scene can't be taken out of the video. Keys work after a click in the viewer (the viewer passes them on). Picking a parent in the breadcrumb loads that element. A slow answer for one element no longer replaces another's. Ctrl+Z undoes only this ad's edits, and the inspector reads the code again after. Knobs show their kind and the code's value even before they're set, with a switch for on/off knobs and Reset; a knob on the element around the one clicked is shown too. Space no longer presses the button that has focus. Sound bars account for a cue that starts into its file.
- **Robustness.** `/api/story` writes to a temp file and renames it; the registry poll survives a file vanishing mid-scan. A filmstrip of a scene that draws with WebGL is one frame, so a 3D ad doesn't run the browser out of WebGL contexts.
- **Tested.** In Chromium against the running desk, with every ad file restored afterwards: knobs (value, nudge, reset) on a temporary knob in `smoke`; adding, placing, timing, taking out and removing an image; all three ratios playing in step; an audio-timed and a one-component ad; keys after a click in the viewer; a start-only trim; undo refused for another ad; a still rendered with the desk open.

# 3D

Read this when an idea needs depth. There are three ways, and the right one depends on what has to look real.

| Way | Use it for | Cost |
|---|---|---|
| **CSS 3D** (`perspective`, `rotateX/Y`, `matrix3d`) | The product's UI in space: a phone that turns, cards in depth, a screen tilting away. The UI stays real DOM, crisp at any angle, and `validate` can read its text. | Free, instant, in the page |
| **three.js** (`src/parts/Three.tsx`) | Real 3D objects and spaces: extruded logos and brand marks, type and particles in depth, a camera flying through layered planes, simple product objects, a model in GLB. | Free, renders in the page with every other check |
| **Blender** (`mv.py blender`, spec.md §6.3) | Photoreal: depth of field, fog and volumetrics, path-traced light, glass, a photographed place made 3D. | Slow renders on the GPU, separate plates |

For "the app in a moving phone", use CSS 3D: the screen is the UI in code (the real one laid out as the app is, or the pitch's enhanced version), inside a phone frame you rotate. Don't paint the UI onto a texture in three.js, because it blurs at an angle and `validate` can't see its words.

A reimagined UI can also leave the screen and become objects: a job card extruded into a physical card, a button turned into a key you press, an answer that drops onto a desk. Build those in three.js (or as CSS 3D layers pulled apart in depth), in the brand's colours and shapes, and put any words a viewer reads in DOM on top, lined up with the object.

## three.js

```tsx
import { Three } from "../../parts/Three";

<Three
  setup={({ THREE, scene, camera, texture, model }) => {
    scene.add(new THREE.AmbientLight("#fff", 0.5));
    const logo = model("ads/<slug>/logo.glb");                      // fills in once loaded; captures wait for it
    scene.add(logo);
    return { logo };
  }}
  draw={(f, { logo }, { camera }) => {
    logo.rotation.y = interpolate(f, [0, 60], [-0.8, 0], { ease: easings.outCubic });
    camera.position.set(0, 1, interpolate(f, [0, 90], [9, 6]));
    camera.lookAt(0, 0, 0);
  }}
/>
```

- **`setup` builds, `draw` moves.** `setup` runs once and returns the objects. `draw(frame, objects, kit)` sets everything that changes from the frame alone, and then the part renders. Any frame can be asked for in any order, so `draw` can't depend on the frame before.
- **Nothing keeps its own time:** no `clock`, no `requestAnimationFrame`, no `AnimationMixer.update(delta)` (set `action.time` from the frame instead), no physics stepped by delta. Scatter with `random(seed)`. A simulation is computed from frame 0 each time, or baked into data first.
- **Text a viewer reads is DOM, on top.** Words drawn inside WebGL are invisible to the Layout, Truth and Hebrew checks. Put the canvas behind, and the type over it, as `src/ads/three-demo/` does.
- **Textures and models** come through `texture(src)` and `model(src)` from `public/`, which hold the capture until they've loaded. Copy brand files into `public/ads/<slug>/` first, as for any asset.
- **Light like a product shot.** A soft key, a fill and a rim, `MeshStandardMaterial` or `MeshPhysicalMaterial`, and the brand's colours. Shadows from a `DirectionalLight` work, and cost a little render time.
- **Each ratio is its own shot.** The canvas is the video's size by default, and the camera's aspect follows it, so move the camera or `lookAt` point per ratio (a `Layout`) rather than shrinking the scene.
- **Check it like anything else:** `bun run stills <id> --frames … --sheet` to look, then render. `validate` redraws random frames on fresh pages, which catches anything that doesn't come out the same twice.

Imports from `three/addons/…` (loaders, `TextGeometry`, `RoundedBoxGeometry`) are fine. Post-processing (bloom and the like through `EffectComposer`) isn't wired into `Three` yet: the part renders the scene once per frame. If an idea needs it, add it to the part, rendering the composer from the frame in place of `renderer.render`, and check it with `validate` before you rely on it.
